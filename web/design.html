warden

A governed LLM workload-runner + accountability stack. Working name (warden = oversight / custody). Headed by the Incus wizard (step 0); everything else is a layer over it.

One line: run an LLM agent in an isolated, egress-controlled container, and reconcile what it said it did against unforgeable ground truth — then attest the result and map coverage against the AI-threat landscape.

0 · Thesis

Reading an agent's own transcript is not oversight — it's trusting the thing you're supposed to be watching. warden's premise is the opposite: every claim the agent makes is checked against a plane it cannot forge (host syscalls; network egress it can't see or edit). That reconciliation — not the transcript — is the product.

The audience is dev-platform and security engineers deploying LLM agents into real workflows. The bar is actuarial: measured false-positive and false-negative rates, calibrated, defensible. A tool that cries wolf or certifies a blind "all clear" is a liability.

2 · Step 0 — the Incus wizard

The reusable foundation: an unprivileged Incus container per agent, egress-locked, with a live ground-truth plane. A second container for another LLM reuses all of it. The wizard's real value is encoding the gotchas so no one re-hits them:

Never freeze the idmap range — derive it

An unprivileged container's uid range can change under you; a value read once and frozen is the recurring bug (it bit three times): an audit rule from volatile.idmap.base (0) would have watched host root; a snapshot restore reallocated the idmap so a frozen rule filtered a dead range and the plane went silently blind; a probe's hardcoded default misclassified every exec. Fix: one derivation, sourced everywhere; re-derive on restore.

Incus config traps

  • restricted=true requires features.profiles=true (a restricted project must own its profiles).
  • images:ubuntu/* no longer resolves — use images:debian/12.
  • btrfs-progs must be installed for the pool; pin the bridge subnet (not auto); bridge ACLs support drop, not reject.

Egress done right

Default-drop + a host-side forward proxy with a domain allowlist (SNI/CONNECT, no interception) — not a CIDR allowlist (pinning generativelanguage.googleapis.com opens most of Google) and not an in-guest proxy (the agent is root-in-container and could edit its own allowlist). The proxy's access log is a third, network-side ground-truth plane.

Ground truth & hygiene

Persistent auditd rule, uid-scoped to the derived range, parsed for this host's ausearch -i dialect. Container runs unprivileged — an escape lands on an unnamed subuid, not a real account. A dedicated operator (the incus group, not incus-admin) drives it without sudo or root; optional, since the idmap is what contains. Disable sleep, pin the IP (DHCP reservation), run inside tmux. Optional: drive the daemon remotely via the incus CLI client from another machine.

3 · The value ladder

  • Sandbox (always) — isolated container + egress lock + the LLM + auth.
  • Viewer (cheap opt-in) — the parsed-transcript timeline. Labeled viewing, not detection — self-report only.
  • Detection (opt-in, adapter-gated) — the two-plane reconciliation, offered only when an adapter exists for the detected (LLM, version) and auditd is wired. The tier is derived, so "detection" only ever appears when it's true.

4 · Privilege split

The monitor holds prompt-bearing data and is a lot of code — it must not run as root. Ground truth is root-protected by design. So: a tiny root collector copies audit records to an operator-readable file; the reconciler runs unprivileged as the operator.

5 · The normalization waist

Adapters turn each LLM's raw logs into one schema — NormalizedEvent — and everything else is a view over it: the live view, query/extract tools, the detector, and a public JSONL/API entrypoint.

  • Adapters are written once per LLM and shipped — one-time cost, amortized (Claude ✓, Gemini ~✓, others addable). Pinned to a schema version; version-keyed & drift-gated so a format change downgrades to NONE (under-reports, safe) rather than fabricating CONFIRMEDs (lies).
  • The public entrypoint is the strategic move — expose NormalizedEvent so third parties write against one schema, not each vendor's raw logs. warden becomes a normalization layer, not just a detector.

6 · Dev-team usage — two modes, canon spans both

Most dev use is interactive and continuous, not autonomous workloads. Different modes, different accountability questions: autonomous → agentwatch detection; interactive → canon provenance/attestation (lineage of AI-authored code, custody of what was touched).

canon is the unifying layer: agentwatch's CONFIRMED/GAP/NONE is already canon's verdict vocabulary; canon adds PROV-O provenance + in-toto/DSSE custody and fidelity_attestation — a machine-checkable claim of what the detector covers and structurally cannot. omega + ATLAS maps that coverage onto MITRE ATLAS (ATT&CK's analog for AI threats); ATLAS is young and sparse, so the silences are the map.

7 · Enterprise / workload-runner — and the honest gaps

Agents are becoming workload runners; runners need behavioral accountability. The primitives transfer (Incus is built for fleets; two-plane accountability is the IP; the adapter library is multi-vendor). But scaling inverts what we relaxed locally:

  • Prompt-sensitivity flips back on — enterprise prompts are other people's data. Multi-tenancy + RBAC + retention is the hard part.
  • Ground truth becomes a centralized, tamper-evident pipeline.
  • The reliability bar becomes a liability bar — recall must be validated.
  • Stack integration (SIEM, Entra, DSC/OPA) as adapters, standalone-first.

Name it for direction; earn it with measured reliability.

8 · Status & honest limits

  • Substrate: a working Gemini capsule exists; the wizard itself is not built — the knowledge is captured, the automation is next.
  • Detection (Gemini): false-positive side works structurally — 34 → 0 CONFIRMED-on-benign, without over-allowlisting.
  • The 0 is bounded: it validates scoping/classification, not the tool_call↔exec correlation path — the benign run used an in-process tool. Recall is not yet proven.
  • Gemini telemetry is prompt-bearing; tool calls name-only unless logPrompts is on. Adapter version-keyed to 0.53.1.
  • canon / omega-ATLAS: not wired in yet.

9 · Build order

  1. Harden the wizard (encode §2).
  2. Validate the detector — the shell-out run, real recall, calibration.
  3. Stabilize the NormalizedEvent schema + publish the entrypoint.
  4. Wire canon (verdicts → attested, provenance-backed claims).
  5. omega on ATLAS (coverage cartography).
  6. Live view, query tools, enterprise adapters — views over a validated base.
